SLIDE 05

The DFA — One Exact Move Per Input

PLAYER 2 2:00-3:00

Thanks, Player 1 — Level 1 is mine. Formally, a deterministic finite automaton is a five-tuple: M equals (Q, Sigma, delta, q-zero, F). Q is the states — what our enemy is doing: S0 idle, S1 tap-one, S2 dash. Sigma is the alphabet — controller events per frame: t is a tap, o is any other input. Delta is the rulebook: a state plus a symbol gives exactly one next state — never a choice, never a maybe. That is determinism: one memory lookup per frame, which is why engines love DFAs. q-zero is the spawn state, always S0, and F is the accepting set — just S2, the frame the dash fires. Acceptance means the input string ends in t-t — the double-tap detector. Next slide: the full transition table and a live trace.

SLIDE 06

Transition Table & Deterministic Trace

PLAYER 2 · handover to P3 3:00-4:00

Let's read the rulebook as a table. Three states, two symbols — and notice every cell holds exactly one move. Now watch the engine trace the input t-o-t-t. First chip: t takes S0 to S1 — one tap logged. Second chip: o is any other input, and S1 falls straight back to S0 — wrong rhythm, the engine resets. Third chip: t again, S0 to S1. Fourth chip: t — S1 jumps to S2, so the dash fires. Accepted! Now the contrast: t-o ends in S0 with no dash — rejected. So the language this DFA accepts is exactly the set of strings ending in t-t: the double-tap detector. Same state plus same symbol always gives the same next state — determinism, one memory lookup per frame. That closes Level 1. Player 3, the boss brain is yours.

SLIDE 08

The NFA — Many Moves, One Energy Bar

PLAYER 3 4:35-5:40

Here's the boss: the Konami code — up, up, down, down, left, right, left, right, B, A — can appear anywhere inside a long input stream, so the engine keeps a scanner state s that eats any symbol and stays in s. On the first up-arrow it also branches into c1 — two live choices at once. That's nondeterminism: the machine explores every branch in parallel. We also get epsilon-moves: state switches that consume no input at all. Now the punchline — subset construction. A DFA simulates the NFA by tracking the SET of states it could be in, like fog-of-war tracking. Worst case that set explodes to two-to-the-n states, but the accepted language is identical. So NFAs and DFAs accept exactly the same languages — nondeterminism buys convenience, never extra power.

SLIDE 09

Patch Notes — Minimization + Moore & Mealy

PLAYER 3 · handover to P4 5:40-6:25

Before we ship the boss, two patch notes. First, minimization: two states that answer every possible future input identically ARE the same guard — the table-filling algorithm merges them. Fewer states mean cheaper, faster AI, and Myhill-Nerode says a language is regular exactly when it has finitely many of those behaviour classes. Five states become three, zero gameplay lost. Second, machines with output. Moore paints output on the state — the HP bar's green, amber or red depends only on which state you're in. Mealy paints it on the arrow — the hit-spark fires exactly on a transition, state plus input together. Any Moore machine converts to a Mealy machine and back. Player 4 — combo mode is yours.

SLIDE 11

Regular Expressions — The Combo Language

PLAYER 4 6:55-7:55

[PLAYER 4 · 6:55–7:55] Level three continues — we stop listing states and start writing patterns. Regular expressions are the combo language, built from three operators. Union means "or": a union b accepts a or b. Concatenation means "then": a b fires a immediately followed by b. Kleene star means "repeat": a-star is zero or more a's — and binding runs star, then concatenation, then union. Two game examples. Input buffering: W-star A — any number of walk frames, then attack fires; one expression, infinite combos. Name check: a letter followed by letters, digits or underscores — the chat engine validates every new player name with one regex. Every regex compiles into a machine: Thompson construction builds an NFA with epsilon-moves, subset construction converts it to a DFA, and minimization delivers the optimal DFA. Going backwards, state elimination with Arden's theorem turns the automaton back into a regex.

SLIDE 12

The Wall — Why Finite Memory Is Not Enough

PLAYER 4 7:55-8:40

[PLAYER 4 · 7:55–8:40] Every power-up has a wall — this is ours. The boss that counts demands n jump-charges and exactly n releases: the language a-n-b-n. The pumping lemma in plain words: if a language is regular, every long-enough string splits into x, y and z — y is non-empty, x-y stays inside the first p symbols, and pumping y any number of times keeps the string legal. Demolition: choose a-p b-p. Since x-y fits within the first p symbols, y can only hold a's. Pump twice — more a's than b's, so the pumped string is rejected. Contradiction: not regular. No DFA or regex can verify it. Counting needs memory that grows — a stack. That's Module four: pushdown automata.

It's Everywhere — Real Game Engines

PLAYER 1 returns 8:40-9:25

[PLAYER 1 · 8:40–9:25] Player One back on the mic — and the achievement list is glowing. Pac-Man's ghosts have run scatter, chase and frightened as a classic finite state machine since 1980. Unity and Unreal animators literally are state machines — the states, transitions and conditions you drag on screen are the delta function. Chat and cheat filters scan text and inputs with regex pattern matching — the same finite-automaton power, live in multiplayer. And fighting-game combos sit in an input buffer until a DFA-like recognizer fires the special move on the exact frame. But here is where it ends: balanced dialogue trees, undo systems, inventory counts — finite automata cannot count. For that, games hand over to stacks and parsers. Modules three and four are waiting.
